**`MatchController`** = server-only 9-phase machine (Lobby→RoundStart→GameSelect→GamePlay→GameResolve→ChaseInProgress→ChaseResolve→RoundEnd→GameOver), `Instance` singleton, `Update()` bails on clients. Chase is event-driven: `ReportEscape`/`ReportCaught` (Stalker calls Caught on contact) resolve it. Dungeon is PRE-BUILT at GameSelect to mask the navmesh hitch. Bench cooldown (1 round) ticks at ChaseResolve so a caught player spectates the whole next round.

**`DungeonGenerator`** (~1500 lines) = seeded room-graph GRID generator. Rooms stamped on a cell grid; touching rooms open via shared-wall doorways, others bridged by A* corridors (Kruskal MST + loop factor; A* state = (cell, arrival-dir) so `turnCost` yields long straight runs; `openBlockCost` avoids 2×2 blocks → no pillars/wide sightlines). Only `DungeonGenerator._seed` + `DungeonObjective` flag are NetworkObjects — every client rebuilds identical geometry locally. Runtime NavMesh bake (voxel ~0.1) + a NavMeshLink per doorway + connectivity guard that rerolls the seed (up to 6×) if anything's stranded. Modular Blender kit is a TOGGLE (`useKitPieces`, currently OFF → greybox). Debug key G regenerates. **PARKED plan** to make size track loser-count via "fewer rooms on a fixed grid" (windowed generation) + object POOLING to replace destroy-and-rebuild — do AFTER the dungeon modelling phase (`Dungeon_Preload_And_Windowed_Generation.md`).

**`StalkerAI`** = server-authoritative, positional-only sensing (design locked 2026-07-17). 4-state (Hunt/Chase/Search/Reacquire); 180° vision cone + range (~18m) + Linecast LOS on `sightBlockers` wall layer — CANNOT hear you, only sight. Loses you → searches last-seen spot leading past it → times out → Reacquire snaps to nearest room centre → Hunt. Lunge burst on cooldown; catch at ~1m. `headStart` ~3s. **Behaviour feel UNTESTED — needs a live chase to tune.**

**The slice's FUN is UNPROVEN at 3-client — the deferred playtest gate** (`Playtest_Plan_3Client_VerticalSlice.md`). Vertical-slice scope locked 2026-07-17 (`VerticalSlice_Scope.md`): fun-validation not marketing, judged by "would you play another round?"; polish concentrates on horror chase + Old Maid; game feel/juice IS in scope. **Riskiest open design question: does the lobby's outcome-BETTING keep non-chased players engaged, or is it dead air?**
